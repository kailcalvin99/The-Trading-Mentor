# LifeOS Development Rules

LifeOS should be developed as a simple, modular, and intentional system. Future implementation should follow the documentation foundation in this folder.

## Core Rules

- Keep LifeOS simple and modular.
- Do not add distracting features.
- Every feature must support intentional living, execution, or clarity.
- Documentation should guide implementation.
- Do not modify unrelated Trading Mentor code unless specifically requested.

## Product Direction

LifeOS should prioritize calm utility over feature volume. New features should make the system easier to trust, easier to use, and easier to leave once the user has what they need.

Avoid features that encourage endless browsing, unnecessary checking, noisy dashboards, or artificial urgency. LifeOS should help users reduce mental clutter, not create more of it.

## Implementation Guidance

Before adding a future LifeOS feature, confirm that it supports at least one of these purposes:

- Intentional living
- Clearer execution
- Better prioritization
- Reduced mental clutter
- Reflection and improvement
- User ownership and control

If a feature does not support one of those purposes, it should not be added.
